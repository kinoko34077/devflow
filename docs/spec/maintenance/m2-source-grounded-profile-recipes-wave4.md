## 1. Census, distinction and eligibility

Exactly **51 unique open `[REPO] <repo>` Controls** were live-searched (2026-10-16) and all 28 not listed in the preceding 20-proposal designs or three existing accepted PILOT catalogs were read through their **individual devflow Control**. Their actual repository README / canonical project spec or source/content files were inspected from the existing default ref, with missing README replaced by the declared local specification where found. Per-file reads are individually current only at observation; different files are **not** proven to form one atomic cross-repo HEAD snapshot.

The names below account for **all remaining 28 without duplication**, and are classified as:
- `PROPOSED` or conditional domain label: **23** substantive product/policy/research services/consumers with *potential* repo-local scope/Lens/Depth design, not execution/adoption.
- `FIXTURE_ONLY`, `VALIDATION_FIXTURE_ONLY`, `EPHEMERAL_TEST_FIXTURE`: **3** existing test/validation repositories. Their owner-defined narrow fixture checks can be relevant, but no regular product audit, scheduled maintenance or blanket new source supply is authorized by their existence.
- `NO_SOFTWARE_LIFECYCLE`, `PLACEHOLDER_NO_LIFECYCLE`: **2** content/placeholder repositories. No runnable application entry existed in observed Control/source; **proposed not to enroll as product code-audit slots** unless owner creates a real source/spec/verification contract.

Thus fleet routing is **3 already accepted SMC PILOT + 20 earlier proposals + 23 new substantive proposals + 3 narrowly scoped fixture-only + 2 no-software/deferred = 51 Controls accounted for**. This is a planning classification, **not** 48 live catalogs, 46 completed audits, 51 full source audits or current fleet readiness. Repo Control `Risk` classification is not permission to downclassify component security/privacy/real-time boundaries.

## 3. Applicability and adoption evidence contract

1. **Two distinct decisions:** “Design candidate exists” is not “source available for audited execution,” and “Control has a previous `AUDITED` label” is not “all scopes and Lens × Depth have current authentic audit credit.” Real audit requires `repo × code/component selector × Lens × Depth × exact relevant repo/ref SHA × catalog digest × external evidence version`, a positive and negative case, the run/Issue owner and reproducible output. Unknown/excluded statuses remain visible.
2. **Historical or test-only snapshots:** The three fixture repos have no product/fleet eligibility merely from their successful one-time test. `stackedit.io` and `Mapience-prototype` are **explicit defer/no-code-scope** rather than falsely backfilled `MAINTENANCE` success. `.ai-guidelines` is standards/policy content; devflow remains mutable cross-repo operational authority.
3. **External/Human negative gates:** `srt2subtitle` remote auth explicitly deferred; `txt-auto-replace` privacy #23 not resolved; `kinotch-judgment-learning` OAuth owner-only admission/security holds; `raindrop-bookmarks-organizer` live API changes require explicit effect permission; `Micro-Chordbot` ZIP workflow disabled. `lyric_reader_page` physical Safari acceptance cannot be inferred from emulator; `github-history-archive` hosted job without executed steps cannot be called CI PASS; `standby-display` official/public deployment distinct from main. No credential or publication mutation here.
4. **Private/public separation:** `testapp` and `kinotch-knowledge` have private Issue/auth/export boundaries: this PUBLIC design file contains **only high-level scope and paths already provided by public Controls/readme**, no private issue titles/catalog bodies, tokens, conversation content or personal records. `kinotch-emergence-lab` excludes `map-data-semi-automation` from its **own research** even though that other repo is managed separately.
5. **Activation path:** A future per-repo catalog requires own accepted authority/source-current owner Issue, explicit supported schema, grounded scope/risk/exclusion, correct branch handling, required CI/formal Review/post-main, existing SMC publisher/claim/RunRecord gates, and real verified evidence. Neither this document nor its merge creates a fourth PILOT, publishes external results, or starts M5 execution. `NO_SOFTWARE_LIFECYCLE` requires new accepted source/spec first; fixture-only requires a dedicated justified fixture maintenance plan.

## 4. Concrete audit depth examples

- `CONTROL`: validate repo-local Control/Issue/PR/Review/action/ownership and source authority; no code Lens gets execution credit.
- `STANDARD`: execute a bounded, version-pinned normal+failure test for the **selected scope**, e.g. `bmp2png-pdf` corrupt mid-batch without PDF publication, `Micro-Chordbot` IndexedDB `READ_FAILED` no overwrite, `memory-game` malformed CSV preserving old pair list, `github-history-archive` malformed edit page manifest unchanged.
- `DEEP`: replay on independent inputs / property-based/physical environment where justified, e.g. `algoram` cross-adapter route authority, `srt2subtitle` authenticated Worker ingress after explicit Human decision, `standby-display` physical low-power Safari and production assets, `lyric_reader_page` actual owner iPhone input and selection. Deepening does not fabricate the missing external input or human approval.
- `N/A` and `HOLD` must retain reason, owner, effect boundary and exact recheck condition; do not represent a policy-mandated deferred external API as a code failure or a completed audit.
