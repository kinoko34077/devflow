# M9 offline workflow dispatch/run identity evidence shape fixture

Status: **OFFLINE_ONLY / NOT AUTHENTICATED / NOT DISPATCHED**. Owner: [devflow #437](https://github.com/kinoko34077/devflow/issues/437), parent [#413](https://github.com/kinoko34077/devflow/issues/413), reviewed Phase4/5 design [#433](https://github.com/kinoko34077/devflow/issues/433) and independent reviewer F1/F2 remediation [#6108465462](https://github.com/kinoko34077/devflow/issues/433#issuecomment-6108465462).

This module accepts an untrusted expected pin and **synthetic, caller-supplied** GitHub REST response objects only. It rejects wrong run IDs, cross-repository URLs, mismatched repository identity, ref, workflow identity and commit SHA; it never makes HTTP requests or calls GitHub Actions. Both successful statuses are deliberately prefixed **OFFLINE** and explicitly say **NOT_AUTHENTICATED / NOT_EXECUTED**. They are **not** permission to dispatch, a transport assertion, a claim, a journal receipt, or an Actions execution result.

**Actual REST response-shape reconciliation (2026-10-11):** Independent [Formal Review #5483134032](https://github.com/kinoko34077/devflow/pull/438) raised N1/N2. Read-only live GET on existing public [devflow workflow_dispatch run #38118114901](https://github.com/kinoko34077/devflow/actions/runs/38118114901) and [execution-coordinator run #38126464254](https://github.com/kinoko34077/execution-coordinator/actions/runs/38126464254) confirms that GitHub returns `run.path` as **plain workflow file path without `@ref`**. The offline matcher requires exact plain `run.path` and independently checks the allowed `head_branch`, `head_sha`, workflow numeric ID and event. A real tag-ref run's full behavior remains unproven; runtime must fail closed until its exact shape/protected immutable ref is independently demonstrated. A rerun `run_attempt >= 2` is rejected; it cannot be substituted for the initial dispatched run or be accepted as safe execution. The pin repository case must come from authenticated canonical GitHub repo metadata; branch refs are *only* valid if a future authenticated adapter verifies effective immovability/protection. All fixture inputs remain unauthenticated.

GitHub announced on [February 19, 2026](https://github.blog/changelog/2026-02-19-workflow-dispatch-api-now-returns-run-ids/) that `POST /actions/workflows/{id}/dispatches` can return `200` with `workflow_run_id`, `run_url`, `html_url` when `return_run_details=true`. A legacy `204`, timeout or a response without an identifiable run ID is **ambiguous**; consumers must not guess an Actions run from timestamps or retry the POST automatically. [API reference](https://docs.github.com/en/rest/actions/workflows?apiVersion=2022-11-28).

The `ref` passed to workflow_dispatch is **branch or tag**, not a directly pinned commit SHA. Before any future M9 privileged launch a **separately reviewed authenticated** implementation must verify repo numeric ID and exact source workflow blob/commit SHA, effective protected immutable ref ruleset, authorized typed actor/inputs, a durable idempotent request ID and sole existing execution-coordinator claim/lease. It must enforce job-side **pre-effect** exact SHA/ref guard; a post-launch cancel cannot prevent an earlier malicious step. It must then bind the actual returned run ID to the request receipt, fetch exactly that run, confirm its GitHub API provenance + event/repository/workflow/ref/head and execution/guard outcome, fail closed on discrepancies and handle uncertainty without duplicate dispatch.

This offline helper does **not** check immutable-ref protection, GitHub API transport/authenticity, policy admission, job guard, workflow blob, actual running jobs, token scope, billing/runner availability, stale dispatch recovery or durable journal. These are intentionally required but separate **M9 NO-GO** items, not gaps silently filled by structural matching. It does not replace or duplicate [#223](https://github.com/kinoko34077/devflow/issues/223), [#395](https://github.com/kinoko34077/devflow/issues/395), [#384](https://github.com/kinoko34077/devflow/issues/384), or execution-coordinator #3. G2B0 C3-B Private metadata-only proof [#424](https://github.com/kinoko34077/devflow/issues/424) stays HOLD_B; C6 approvals remain distinct.
