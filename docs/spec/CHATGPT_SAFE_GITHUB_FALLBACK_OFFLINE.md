# Native-first GitHub dispatch fallback — decision contract (offline only)

Owner: [devflow #448](https://github.com/kinoko34077/devflow/issues/448), parent [#413](https://github.com/kinoko34077/devflow/issues/413). User decision 2026-10-12: **normal workflows and Public repositories use the connected GitHub app; fallback exists only for operations the app lacks or when Private GitHub-hosted runner free capacity is exhausted**.

## Delimit responsibilities before picking a provider

| Concern | Default | Fallback trigger | What a fallback must NOT imply |
| --- | --- | --- | --- |
| GitHub API data / PR / Issues | Existing connected GitHub typed tools, existing owner authorization | Required **exact** operation not offered or denied by actual connection | An external Cloudflare/Deno service has no inherited GitHub token, consent, scopes or user identity |
| GitHub Actions fixed reviewed operation | Supported repo-native fixed trigger + standard GitHub-hosted runner when runnable | Verified Private hosted-minute/budget exhaustion | Missing general `workflow_dispatch` is NOT cured by changing the runner |
| Compute outside hosted Actions | None by default | Private hosted runner exhausted, or an operation cannot run under Actions | Self-hosted is not free operationally, has persistence/security risks, and cannot bypass **all Actions disabled** |
| Reliable one-time dispatch | Existing execution-coordinator#3 claim/lease and #384 verified writer when applicable | Genuine missing authorized transport | Never add a parallel claim queue, silently weaken exact SHA, or treat an Issue comment as privileged authorization |

### Evidence and zero-base decision order

1. **Does the current installed GitHub connection support this exact operation?** Inventory actual typed tools or invoke allowed read-only metadata; do not infer broad capabilities from a connector name. If supported, stay native. The existing connector can read Private canary metadata/HEAD but does not expose general workflow_dispatch.
2. **Is the requested operation API-only or does it need real process/OS compute?** An API-only operation should NEVER consume runner minutes merely because a workflow exists.
3. **For fixed Actions:** prove a trusted trigger for exactly that versioned/pinned operation; `#395` seeded fixed /kinotch status Public pilot is **not general-purpose command execution**. GitHub REST `workflow_dispatch` needs `Actions:write` and a separately authorized trusted caller; `repository_dispatch` needs `Contents:write` and is NOT a least-privilege replacement.
4. **If PRIVATE Actions doesn't start, diagnose rather than guess:** distinguish paid-hosted minutes used, exhausted included quota, zero-dollar blocking budget, account Actions disabled, runner unavailable, workflow disabled, bad permissions, and first-job error. A single failed run cannot prove budget exhaustion. GitHub official budget document says exhausted Actions **product budget can block GitHub-hosted runners**; it does not establish universal self-hosted scheduling under all account disablement causes.
5. **If only Private hosted minutes are exhausted:** a pre-approved, isolated, dedicated single-repository **self-hosted** runner can be a non-GitHub-billed candidate if Actions remains enabled, matching fixed workflow+trigger+permissions. No self-hosted infrastructure is currently admitted here. If Actions itself is disabled, use a **separately approved external compute/transport** or HOLD; no automatic fallback. Never run untrusted PR code in a persistent secrets-bearing host.
6. **If no fixed authorized route exists:** HOLD with a concrete missing requirement. Do not create a new App/OAuth session, token, paid resource or public bridge merely to keep progress moving. Human security/expense gates remain separate.

- Workflow/API auth: [workflow_dispatch REST](https://docs.github.com/en/rest/actions/workflows), [Private branch GET](https://docs.github.com/en/rest/branches/branches) and [Git ref GET](https://docs.github.com/en/rest/git/refs). HEAD requires `Contents:read` for the existing tested Private App path. C3-B `Metadata:read` GraphQL trial is **FAIL_B**; no retries.

## Offline planning module

`tools/safe_dispatch_fallback.py` has a pure `plan_fallback(G1Admission, EvidenceSnapshot)` interface. It is NOT connected to GitHub transport. `EvidenceSnapshot` is **untrusted caller-supplied evidence** until a future adapter independently verifies its provenance.

- Returns only `PLAN_ONLY` (possible route, no authority) or `HOLD`. Never `ADMITTED`, `EXECUTED`, `READ_VERIFIED`, run ID, credential or receipt.
- Preserves the accepted trusted G1 backend; no request-selected replacement backend, credential, runner command, arbitrary URL or user-provided shell.
- `GITHUB_CONNECTOR_INTERACTIVE` means a currently typed interaction only, not a G1/G2A certified machine result. `GITHUB_HOSTED_FIXED_WORKFLOW` and `PRIVATE_SELF_HOSTED_FIXED_WORKFLOW` are **candidates**; no invocation, runner registration or scheduler proof.
- `private_quota_exhausted` is an independently established **current included-minute depletion**, **not** inferred from a failed workflow. `private_billing_blocked` is distinct: the observed provider text can represent failed payments or a spending-limit restriction, and on its own returns HOLD pending fresh runner eligibility. `all_actions_disabled` explicitly prevents self-hosted runner selection.
- Unreviewed API path, unknown quota, missing fixed dispatch and missing isolation/Human approval all return HOLD. Tests run entirely offline.


## Concrete observed capability gaps and cheapest available routes (2026-10-12, #450)

The result of the 2026-10-12 GitHub connector inventory is **not** "GitHub has no Actions APIs." GitHub **does** expose `workflow_dispatch`; the installed ChatGPT GitHub connection **does not provide that typed action**. The connection **does** provide owner-authenticated Issue creation/comments and PR/commit operations. Before requesting another App or OAuth grant:

1. **PUBLIC / fixed pre-approved command:** The already accepted [#395](https://github.com/kinoko34077/devflow/issues/395) receiver [`kinotch-repo-command.yml`](https://github.com/kinoko34077/devflow/blob/main/templates/bootstrap/kinotch-repo-command.yml) uses an `issue_comment` event, exact `/kinotch status`, owner/sender identity checks and `ubuntu-latest` to perform a fixed read-only task. A ChatGPT-authored approved Issue comment can enter that already built route **without granting another OAuth token**. This is only the tested fixed `status` operation, **not a generic workflow launch**. Each new command requires separately pinned fixed behavior and proportionate source review. Never interpolate arbitrary comment text as a shell command.
2. **PUBLIC / missing `workflow_dispatch`:** If an actual required operation needs `POST /actions/workflows/{workflow_id}/dispatches`, GitHub's documented fine-grained token requirement is `Actions:write`. A future owner-only fixed Issue-command receiver could invoke a **specific reviewed workflow** with its job token after a concrete security/permission review; this is a future **effectful widening** beyond the present receiver's `permissions: {}` and job-level `contents: read`, not an already available permission-free path. Treat the old `status` command as evidence of triggering capability only.
3. **PRIVATE / suspected hosted-minute exhaustion:** GitHub personal billing usage can be queried through [the user billing usage-summary REST endpoint](https://docs.github.com/en/rest/billing/usage#get-billing-usage-summary-for-a-user), whose fine-grained user-token requirement is **`Plan:read`**. This exact endpoint is NOT currently exposed among the connected GitHub typed operations. The historical PRIVATE #395 [run 37979918351](https://github.com/kinoko34077/kinotch-repo-native-dispatch-pilot-20261009/actions/runs/37979918351) had no job steps; on 2026-10-12 an already authenticated owner-local `gh api` **read-only check-run annotation** attributed its failed launch to a **generic account billing/spending-limit gate**. This proves a **historical billing/spending gate**, not exhausted included minutes, which exact billing condition applied, or the current account state. DO NOT silently reclassify it as `private_quota_exhausted`. An actual owner-visible [billing usage overview](https://github.com/settings/billing) may be used when troubleshooting a *real* blocked operation; never demand another OAuth session just to refine a speculative fallback plan.
4. **PRIVATE / truly exhausted hosted allowance:** [GitHub's current billing docs](https://docs.github.com/en/billing/concepts/product-billing/github-actions) say standard Public hosted and self-hosted usage is currently free, while PRIVATE standard hosted consumes included minutes. A proposed 2026 self-hosted-minute surcharge was [explicitly postponed](https://github.blog/changelog/2025-12-16-coming-soon-simpler-pricing-and-a-better-experience-for-github-actions/). A dedicated, protected [self-hosted runner](https://docs.github.com/en/actions/concepts/runners/self-hosted-runners) could run fixed jobs without GitHub-hosted-minute charges **only if Actions remains enabled and the runner matches `runs-on`**. This still needs installation and isolation. Automated per-repo [JIT registration](https://docs.github.com/en/rest/actions/self-hosted-runners#create-configuration-for-a-just-in-time-runner-for-a-repository) requires **`Administration:write`**, not just `Actions:write`; it is a high-risk permission boundary, not an invisible/zero-auth fallback. GitHub [explicitly warns](https://docs.github.com/en/actions/reference/security/secure-use) that persistent runners can be compromised, including Private PR activity and exposed credentials. Never mount an existing secrets-bearing desktop as a general untrusted runner by default.
5. **PRIVATE / exact API-only read or write:** Prefer the already connected, user-authorized GitHub typed action whenever it supports the operation, regardless of Private visibility. *API work does not need a runner.* A separate Cloudflare/Deno/other compute service never inherits the ChatGPT GitHub connection's identity or privileges; it needs its own carefully scoped and justified transport. The failed Metadata-only C3-B exact HEAD candidate remains FAIL_B; no further owner token experiments on this candidate.
6. **PRIVATE / actual code execution and no hosted runner:** A bounded existing owner-local execution surface, if already available and separately authorized for that **specific** fixed task, may be a lower-friction alternative than adding another always-on runner/App. Verify trusted local source and expected HEAD; keep GitHub credentials on that host and never emit them in chat/logs; preserve the execution-coordinator claim gate. RDC or remote shell is strictly a last resort, not an implicit authorized background provider. If none of these safe conditions holds, **HOLD**.

### Source/decision discipline

This section narrows earlier high-level candidate descriptions; it **does not** authorize the connector to run a workflow, install any runner or use local existing credentials. When a real fallback is required, first record the exact missing operation, the recognized GitHub connection capabilities, current trusted repo/head, actual Private billing/runner cause, security effect, minimum permissions and projected human work. Then choose `CONTINUE / CHANGE_PATH / SPLIT / HOLD / STOP` using original objectives and external facts. If the sole remaining justification is a speculative platform workaround requiring manual authorization, **STOP rather than shift testing cost/risk onto the owner**.


## New verified fallback route: existing owner-local GitHub CLI and historical billing gate (#455, 2026-10-12)

**Read-only live evidence on the already authorized KiNoTch. owner machine, without another OAuth session:**
- `gh version 2.100.0` installed. `gh api user --jq .login` confirmed the authenticated actor `kinoko34077`. The existing CLI could read the Public `devflow` Actions workflow catalog (10 workflows) and the exact Private canary `main` HEAD `0d72fceacb4cd458564c3269c46d47886e2127a5`. `gh workflow run --help` confirms that the CLI binary supports fixed `workflow_dispatch`, **not** that the current credential has sufficient `Actions:write` scope or any workflow is authorized to run.
- `gh api` retrieved [the historical #395 job check-run annotations](https://github.com/kinoko34077/kinotch-repo-native-dispatch-pilot-20261009/actions/runs/37979918351) without collecting job contents. The provider annotation classified the job launch as **billing/spending-limit blocked**; the message had multiple possible causes, and the precise financial condition remains unknown. The public specification intentionally omits personal billing details. This supersedes the previous absence-of-annotation status, **not** proof of an ongoing issue on the now-Public fixture.
- A single **silent read-only** request to GitHub's personal billing usage endpoint received HTTP 404 with an existing-token OAuth `user` scope requirement. **No `gh auth refresh`, user approval flow, new token or permissions were performed** merely to get a speculative balance. GitHub's fine-grained-token [billing usage documentation](https://docs.github.com/en/rest/billing/usage#get-billing-usage-summary-for-a-user) independently states `Plan:read` for its supported token type.
- Git and Python/Node are installed; Docker CLI is installed, but the Docker Desktop Linux engine was unavailable when checked. **No isolated local execution environment, GitHub Actions runner registration or always-online guarantee has been proven.**

**Revised lowest-friction routing after actual new evidence:**
1. **Connected GitHub typed API first** for Public *and* Private operations it actually supports. Do not automatically remote-shell ordinary GitHub operations.
2. Only for a **specific missing typed API operation**, a currently online, owner-authorized PC with a verified matching `gh` login can be a *noncredential-exporting owner-local fallback candidate*. Plan `OWNER_LOCAL_GH_CLI_API` under the offline router. Before any actual effectful use, independently revalidate identity, exact owner/repository/HEAD, minimum endpoint-specific permission, immutable allowed command and user approval where necessary. **Never issue arbitrary chat-supplied shell, generic `gh api -X POST`, token inspection or cookie/session export.** Do not confuse this native CLI with an always-on unattended service or an authenticated G2B0 adapter.
3. **Private hosted runner billing block** must be distinguished from **confirmed exhausted free minutes** and **all Actions disabled**. The specific 2026-10-09 check-run proves a historical billing gate, not that a self-hosted runner would launch now. `private_billing_blocked` always gives a HOLD until fresh account status and scheduler eligibility are established, **even if a runner was reported ready and approved**. No automation may suppress billing/account errors by changing the runner label alone.
4. If truly isolated compute is necessary in future and GitHub-hosted is unavailable, recheck existing available owner-local environment or specifically approved external job provider; installing Docker, registering self-hosted GitHub runner (`Administration:write`), billing changes and new App/OAuth are **separate security/cost decisions**. No such effects happened in this investigation.

Both new states are **caller-reported observations** in the pure `EvidenceSnapshot`, not authenticated proofs. The pure router emits only `PLAN_ONLY` or `HOLD`. Its `OWNER_LOCAL_GH_CLI_API` output is a candidate for a carefully bounded read/work request, **not authorization to execute on the owner machine**.
